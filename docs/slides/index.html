Hello everyone, I'm Gabe Grand, and today I'll be presenting joint work on building rational agents for discovery.

  • From science to medicine to engineering, many high-stakes applications of AI require seeking information strategically.
  • People are remarkably good at this — we naturally form hypotheses and ask questions to resolve uncertainty.
  • Modern language models, on the other hand, are optimized to answer complex queries — but do they learn to ask good questions for themselves?
  • To study this, we first need a common understanding of what rational exploration looks like.

It turns out that across domains, many discovery problems share a common structure.

  • In each case, we start with a high-level goal that we want to accomplish both accurately and efficiently.
  • The real challenge is the state space. There are combinatorially many possibilities, and we're searching for a needle in a haystack.
  • To narrow things down, we run experiments. But there are also many possible experiments — so we need to choose wisely.
  • Finally, once we've gathered enough information, we can take action. Too much caution here will lead to inefficiency, but overeager behavior could produce disastrous consequences.

This tension -- between exploration and action -- is the central focus of our work.

This work

A framework based on Bayesian Experimental Design (BED) for building and evaluating agents in discovery settings.

  • Part I: Task Design. A sandbox environment for controlled evaluation of information-seeking.
  • Part II: Modeling Framework. Inference techniques that equip agents with a code-based world model.
  • Part III: Experiments & Results. Agents go from random chance to superhuman, outperforming frontier models at a fraction of the cost.

To study this problem, we propose a framework for building and evaluating discovery agents grounded in Bayesian Experimental Design. In this talk, I'll walk you through three parts:

  • First, I'll introduce a controlled sandbox environment that allows us to study info-seeking in both humans and AI agents.
  • Second, I'll describe techniques to improve agents' ability to both ask and answer questions by equipping them with a code-based world model.
  • Finally, I'll highlight some key results: for instance, we find that our approach can boost agents from random chance to superhuman performance; and even outperform frontier models.

Building a sandbox for discovery

  • Fast and scalable. Experiments can be run quickly at low cost.
  • Measurable. A principled way to quantify the value of each experiment.
  • Human-interactive. Both humans and AI can play without domain expertise.

Newell & Simon (1958)

So what would an ideal sandbox look like?

  • Well first, real-world experiments are time-consuming and costly — we need a domain where we can iterate in seconds.
  • Second, we want some way to quantify the utility of an experiment — not just whether the agent succeeded, but whether the questions it asked along the way were good ones.
  • Third, we want to directly compare agents and humans, which means the task has to be simple enough that anyone can pick it up.
  • In both AI and cognitive science, there's a long tradition of using game environments to study decision-making.
  • This tradition extends through present-day research; evals like ARC-AGI show that grid-worlds can still capture complex reasoning tasks.

With these criteria in mind, we turned to a classic board game built around information-seeking...

The Captain's goal, then, is to choose experiments that let them learn as efficiently as possible.

  • We can formalize this with Information Gain, which measures how much the experiment reduces our uncertainty. But we don't know the result in advance...
  • ...so we take the expectation over possible outcomes. That gives us Expected Information Gain, or EIG.
  • Then, the best experiment is then simply the one that maximizes EIG.

While this gives us a clean objective, optimizing it in practice faces several challenges...

Challenges
Computing EIG exactly is intractable in general. Three key difficulties:
Marginalization
Entropy requires marginalizing over combinatorial $s \in \mathcal{S}$.
Simulation
Estimating likelihood of outcome $y$ requires simulating experiment $x$.
Proposing experiments
Experiment space $X$ may be vast or open-ended.
  • First, computing this entropy term on the left requires summing over a *huge* space of possible states.
  • Second, estimating the likelihood of each outcome requires some way to simulate the outcome of an experiment.
  • And third, the space of possible experiments may be vast, so we typically can't just enumerate them all.

Inference-scaling for experiment design: scaling compute leads to more informative experiments.

The Captain observes a partial board and samples full-board hypotheses from the world model. To decide what to ask next, it runs a three-stage pipeline.

  • First, the Captain poses a candidate question in natural language.
  • Next, it translates the question into a Python function that takes a board and returns True or False.
  • The Captain can use the world model to simulate that code against each sampled hypothesis. By collecting the distribution of answers, the Captain can then compute the EIG of the question.
  • By repeating this process, the Captain can determine which of multiple candidate questions is worth asking.
  • Some candidates are redundant — every hypothesis returns the same answer, so the EIG is zero.
  • Others partition the hypothesis space more evenly, yielding higher EIG; these are the ones the Captain should pick.
  • This gives us an inference-time scaling recipe: sampling more questions leads to higher EIG and ideally, better performance.

Using the world model to select when and where to shoot:

  • Better targeting (+0.303–0.374 F1)
  • Superhuman (82% win rate for Llama-4-Scout vs. humans)
  • Surpass frontier (67% win rate vs. GPT-5, 100× cheaper)

We can measure targeting performance using F1 score, which treats hits versus misses as a binary classification task.

  • As expected, random shooting gives a low baseline.
  • Humans do much better, with a wide spread across players.
  • Out-of-the-box LMs are in a similar range: GPT-5 is already competitive with humans, whereas Llama-4 and GPT-4o barely above chance.
  • Surprisingly, we found that just optimizing EIG (InfoMax) did not actually improve F1 on its own.
  • The intuition is that forcing LLMs to ask informative questions isn't enough if they can't use the answers effectively. Luckily, the world model can also be used to guide actions.
  • This delivered dramatic gains:
  • Even Llama-4-Scout, a relatively modest model, went from random chance to superhuman performance.
  • And it even outperformed GPT-5 -- at roughly a hundred times lower cost.

Takeaways

  • Formalizing rationality: Define and measure rational exploration against human and Bayesian baselines.
  • World models as tools: An interactive simulator lets agents test hypotheses before acting.
  • Necessary but not sufficient: Controlled tasks are a prerequisite for trusting agents in real-world discovery.
  • From games to the real world: Same principles apply to agentic coding, medical diagnosis, and scientific discovery.

Let me wrap up with a few takeaways.

  • First, we showed how to define and measure rational exploration, comparing LM behavior against both human and idealized baselines.
  • We showed how agents can use world models as interactive simulators to test hypotheses before acting. This connects to broader ideas around coding environments and agent harnesses.
  • We see these kinds of controlled environments as a necessary prerequisite. If an agent can't explore rationally in Battleship, we probably shouldn't trust it in the clinic or the lab.
  • Finally, we believe these principles around question-asking can extend to domains like agentic coding, medical diagnosis, scientific discovery, and beyond.

To figure out whether to run an experiment, the agent first translates it into executable code. Then, it calls the world model to run that code on each sampled hypothesis, yielding the EIG.

Task

Why Battleship?

  • Combinatorial complexity. Battleship has a simple representation but a large state space, similar to other challenging text- and grid-based tasks like ARC.
  • Minimal closed-loop BED. Battleship instantiates the full Bayesian Experimental Design loop: agents form beliefs, design experiments (questions), observe outcomes, and update.
  • Formalizing rationality. We can quantify the value of each question using Expected Information Gain (EIG), enabling direct comparison between human and LM behavior.

ARC-AGI 2, Chollet et al., 2025

Why Battleship and not some other task? Three reasons. First, unlike ARC or open-ended benchmarks, Battleship has a fully formalized state space with optimal baselines — we can measure degrees of rationality, not just success or failure. Second, it's a minimal instance of closed-loop Bayesian experimental design. Third, we can formalize what a "good question" is using information theory.

Expected Information Gain

Given board $S \in \mathcal{S}$ and question $q$ with answer $a \in \mathcal{A}$:
$\text{IG}(S;\, a) \;=\; H(S) \;-\; H(S \mid a)$ information gain
$\text{EIG}(S;\, q) \;=\; \mathbb{E}_{a}\!\big[\text{IG}(S;\, a)\big]$ expectation over answer
$\phantom{\text{EIG}(S;\, q)} \;=\; H_b(p)$ when $\mathcal{A} = \{0, 1\}$
where $p := P(a\!=\!1)$

Let's build up EIG from standard information theory. S is a random variable over board states — here's one partial board the Captain might see. The Captain asks a question q, like "is there another ship near orange?", and gets a yes/no answer. Information Gain measures how much one answer reduces uncertainty. EIG averages over possible answers — it's mutual information. For binary answers, this simplifies to binary entropy, maximized at p = 0.5.
Framework

Properties of EIG

$\text{EIG}(S;\, q) = H_b(p)$
Assumes a perfect Spotter
Spotter as a BSC with noise $\varepsilon$:
$\text{EIG}_\varepsilon(S;\, q) = H_b\!\big(\varepsilon + (1\!-\!2\varepsilon)\,p\big) - H_b(\varepsilon)$
Here's the key intuition: EIG is maximized when p = 0.5 — when we're most uncertain about the answer. Questions where we already know the answer (p near 0 or 1) have low EIG. In our setting, the Spotter can make occasional mistakes, modeled as a binary symmetric channel with noise rate epsilon. This reduces the maximum achievable information, but questions with p near 0.5 are still optimal.
Framework

How do we estimate EIG?

$p \;:=\; P(a\!=\!1) \;=\; \underbrace{\mathbb{E}_{s \,\sim\, P(S)}}_{\text{board space}} \!\Big[\;\underbrace{P(a \mid q;\, s)}_{\text{semantics}}\;\Big]$
  Challenge 1: The space of possible boards is very large — marginalization over $P(S)$ is intractable
  Challenge 2: Evaluating $P(a \mid q;\, s)$ requires interpreting the semantics of natural language
We need to compute p — the probability that question q gets answer a=1. Expanding this, we need to marginalize over the board space P(S) and evaluate the conditional P(a|q;s) for each board. Two key challenges: first, the board space is combinatorially large, making exact marginalization intractable. Second, evaluating P(a|q;s) requires interpreting what the natural language question actually means with respect to the board.

def answer(true_board, partial_board) -> bool:
    # Columns 1-4 = zero-based indices 0-3
    max_allowed_col = 3
    ship_ids = [s for s in np.unique(true_board) if s > 0]

    count_within = 0
    for sid in ship_ids:
        cols = np.where(true_board == sid)[1]
        if cols.size > 0 and cols.max() <= max_allowed_col:
            count_within += 1

    return count_within >= 2

Before I show the strategies, here's the key building block: a world model. We sample plausible board configurations consistent with everything observed so far, using Sequential Monte Carlo. Marginalizing over these samples gives us a belief state.
